# 지금 할 일

## 지금 당장

### 1) System MCP `disk_free` "비활성화" 응답 — 진단 필요

admin_console에서 enabled로 보이는데 에이전트는 "'disk_free' 툴 비활성화"라고 답함. 이 정확한
문구는 `shared/mcp_caller.py`의 `PermissionError(f"'{name}' 툴은 관리자 콘솔에서 비활성화되어
있습니다.")`에서만 나온다 — 즉 호출 시점에 `system_whitelist_state` 테이블의 실제 `enabled`
값이 false였다는 뜻(admin_console 목록 화면과 같은 테이블을 보므로 화면엔 true였다면 시점 차이나
캐시 문제일 가능성). 확인 순서:
1. admin_console → System MCP 탭 → **실행 로그**에서 `disk_free` 호출 기록 찾기 → `status`가
   `blocked`(사유: disabled by admin)인지, 아니면 `denied`(역할 부족)나 `error`(host 문제)인지
   확인 — 이게 제일 정확한 원인 확인법.
2. 화이트리스트 탭에서 `disk_free` 토글을 껐다 다시 켜서 저장(값을 강제로 다시 씀) → 재질문.
3. 그래도 안 되면 실행 로그의 정확한 `status`/`result` 내용을 알려줘.

### 2) 에이전트가 "어느 시스템이냐" 되묻지 않고 바로 로그인서버로 조회하게

"홈 스토리지 할당량"처럼 서버를 안 밝혀도, 슈퍼컴 관련 질문이면 바로 로그인 서버(현재
`scheduler_login_host` 설정값)로 `disk_free`를 실행해야 한다는 게 요구사항. 지금은 LLM이 host를
몰라서 되묻는다 — 에이전트 지시문(설정 탭 "에이전트 지시문")에 "슈퍼컴/홈스토리지 질문이면
호스트를 [실제 로그인서버 이름]으로 간주하고 바로 disk_free를 호출하라"는 문장을 추가하면
해결됨. 실제 로그인 서버 이름(현재 `scheduler_login_host` 값)을 알려주면 지시문 초안을 만들어
줄 수 있음.

### 3) 매뉴얼 수정 후 재발행 — 이미 되는 기능, 절차만 안내

"업로드한 데이터 수정해서 발행하면 반영되는가?" → 네, 됩니다. 다만 **발행 중인 문서의 청크는
바로 수정할 수 없고** 순서가 필요함:
1. 매뉴얼 탭 → 해당 문서 열기 → **"발행취소"** (draft로 내려감, 검색에서 즉시 제외)
2. 청크 텍스트 수정(이제 편집 가능 — 수정하면 그 청크의 임베딩이 비워짐)
3. **"발행"** 다시 클릭 → 비어있는 임베딩만 새로 계산하고 status가 published로 복귀 → 검색에
   바로 반영됨

완료된 내역/원인 분석은 `docs/RUN-LOG.md` 참고.
